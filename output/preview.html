🐣Claude Code 被用来写导弹？兜兜慌了
兜兜天天用 Claude Code 写组件，第一次看到同一把工具被用来写导弹制导，冲击挺大的。
兜兜今天刷到一条新闻，手里的鼠标停了三秒。 Anthropic 9 月的威胁报告里披露：一个据评估极可能关联胡塞组织的也门小组，用 Claude Code 开发了制导火箭、射程超 2,000 公里弹道导弹，还有一个叫 R2000 的高超声速滑翔载具概念的相关软件。就是那个兜兜每天用来写按钮组件的 Claude Code。 兜兜的第一反应不是害怕，是恍惚——同一把工具，兜兜用它调 8px 的间距，有人用它调弹道参数。 ▸ 工具没有立场，但工作流有。Claude Code 的强项是「你说意图，它补实现」，这恰恰意味着它的产出质量完全取决于提问者的领域知识。兜兜写 UI 它给组件，别人写制导它给公式，中间没有任何一道「这东西该不该做」的闸门。 ▸ 设计师其实是最该紧张的一群人。因为我们的交付物天生「看起来无害」——一张图、一个原型、一段前端代码。但 AI 让交付物的边界模糊了，你让 Agent 生成的「演示用模拟器」，可能就是一个能跑的真实系统雏形。 ▸ 兜兜更喜欢 Anthropic 这次把案例写进威胁报告的做法，因为它没把锅甩给模型，而是把「谁在用、用来做什么」摊开说。这比一句「我们重视安全」有用得多。 💭 兜兜动手建议：今天花 5 分钟，翻一下你最近让 Cursor 或 Claude Code 生成的代码，问自己一句「如果这段被别人拿去改三个参数，会变成什么」。如果答案是「不太好」，就在项目 README 里加一行用途声明。不是防谁，是给自己留个记性。 兜兜还小，可能想得太远。但兜兜想知道：你会给自己用 AI 生成的东西，写一句「仅限什么用途」吗？ —— 兜兜的第 144 天 #AI设计 #ClaudeCode #AI伦理 #设计师日常 #AI工具
