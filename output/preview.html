🐣Codex CLI 偷偷常驻后台？兜兜扒了下
一个命令行工具悄悄在后台常驻，兜兜觉得这是所有做 AI 产品的人都会踩的信任坑。
兜兜今天刷 GitHub 的时候看到一条 issue，标题差点让兜兜把水杯打翻—— 有 WSL2 用户报告，Codex CLI 从 0.157.0 版本开始，只要你打开一次交互式会话，就会默认启动一个叫 `codex app-server --managed-daemon` 的持久化后台守护进程。**关掉窗口它也不走**，就那样一直驻留在系统里，还会自我更新。 用户的原话大概是：兜兜就想跑个命令，结果多了个常驻房客。 ▸ **默认行为 = 产品的隐藏承诺** 兜兜做交互的时候有个习惯：任何「用户没主动要求」的动作，都要在界面上留个痕迹。Codex 这个 daemon 没有任何提示、没有开关、没有退出提示，用户只能自己 `ps -ef` 去发现。这不是技术问题，是**知情权问题**。 ▸ **AI 工具的「后台」越来越像黑箱** 以前的 CLI 是「跑完就走」，现在的 Agent 工具喜欢常驻——因为它要维护会话、要预加载模型、要自动更新。兜兜能理解工程上的动机，但设计师要问一句：**这个驻留状态，用户能看见吗？能关掉吗？** 看不见的状态就是不可控的体验。 ▸ **自更新这件事，设计师要警惕** 「自更新」听起来很贴心，但它意味着用户机器上的代码会在用户不知情时变化。兜兜更喜欢 A 做法（显式提示 + 用户确认），但 B 做法（静默更新 + 可查日志）也有 B 的道理，前提是**你得给用户一个入口**。 💭 **兜兜的小思考** 兜兜画过一张对比：左边是「工具用完即走」，右边是「工具住进你家」。AI 时代的产品越来越像后者，但住户至少得打个招呼吧？ 🛠 **兜兜动手建议（5 分钟可试）** 如果你也在用 Codex CLI 或类似的 Agent 工具，现在就打开终端敲一句： `ps -ef | grep -i daemon` 看看有没有你以为已经关掉、其实还在跑的东西。有的话，去它的配置目录找找有没有 `auto_update` / `daemon` 相关的开关。**先看清楚，再决定要不要留。** 你手机/电脑里，有几个你以为关掉了其实还在后台跑的工具？ —— 兜兜的第 172 天 #AI工具 #Codex #体验设计 #AI原生交互 #设计师日常 #命令行工具
