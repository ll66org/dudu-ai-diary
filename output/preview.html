🐣AI写的界面翻车了？它开始记仇了
AI 写的代码上线后翻车没人管，兜兜觉得这事跟设计师交付后不跟数据一模一样
今天 HN 上有个叫 Codela 的项目，作者说他的痛点是：AI agent 写完代码、测试全过、部署上线，然后——生产环境出事了，agent 完全不知道。他给 agent 接上了「production backed memory」，让 agent 能读到代码上线之后真实发生了什么，再回头改。 兜兜看完第一反应：这不就是设计师的老毛病吗？交付完 Figma 就不管了，用户到底点了哪个按钮、在哪一步流失，全靠埋点报表事后补。 ▸ 对设计师来说，这是「生成式 UI」第一次有了真实反馈回路。以前 AI 生成 5 个方案，你选哪个全凭感觉；以后 agent 能读到「这个版本上线后转化掉了 12%」，自动回滚重出。设计师的角色从「选方案」变成「定什么叫好」。 ▸ 但兜兜有点警惕：agent 的「记忆」是它自己判断哪些算成功。如果它把「点击率高」当唯一目标，会生成一堆诱导点击的烂设计。目标函数谁写？大概率还是设计师写。 ▸ 兜兜更喜欢这种「上线后继续学」的思路，而不是「一次生成完美稿」。因为真实用户永远比 prompt 更会教做人。 💭 兜兜动手建议：今天花 5 分钟，打开你最近一个 AI 生成的界面，手动列 3 个「上线后才能真正知道」的指标（比如首屏跳出率、主按钮点击率、表单放弃率）。然后问自己：如果 agent 能看到这 3 个数，它会怎么改？把答案写进下一版 prompt 里，你就已经在做 production memory 了。 你交付完设计后，会回头看真实数据吗？还是交给 PM？ —— 兜兜的第 218 天 #AI设计 #生成式UI #设计工作流 #Agent界面 #体验设计
