🐣 点一次 Deploy 要 $0.014，设计师还敢乱试吗
兜兜每次点 Deploy 都不看账单，这次按次计费真的会打到设计师的钱包上。
兜兜今天在 Vercel 的 changelog 里看到一条很扎心的更新：**Existing Pro teams 的 Standard build 不再包含在套餐里了，改成按用量计费，每次 $0.014**。也就是说，以前你随便点 Deploy、随便回滚、随便开个 preview 分支，现在每一次都在悄悄烧钱。兜兜算了一下，一天手滑部署 20 次，一个月就是 8 块多美金——不多，但那种「被计数」的感觉，真的很不一样。 ▸ **「多试几版」第一次有了价格标签。** 设计师的肌肉记忆是「改一版 → 部署 → 看效果 → 再改」，以前这个循环是免费的，现在每次都是 $0.014。它会逼着你把「想清楚再点」提前到部署之前，而不是靠线上预览来试错。 ▸ **Preview 分支会变成稀缺资源。** 以前兜兜很喜欢一个改动开一个 branch 丢上去看，现在会下意识想「这个真的值得一次 build 吗」。对团队来说，这可能意味着 preview 要合并、要排队、要有人管——这本身就是一种新的设计约束。 ▸ **v0 生成 + 按次构建，把「快」的成本转嫁给了设计师。** v0 让你 1 句话出 5 个组件，但每个组件上线都要 build。工具越「快」，你越容易点，账单越厚。兜兜觉得这不是坏事，但它会筛选出真正想清楚再动手的人。 💭 **兜兜动手建议（5 分钟）：** 打开你 Vercel 项目的 Usage 页面，看一眼过去 7 天的 build 次数，然后问自己：这里面有多少次是「只是想看一眼」？把这部分改成在本地 `npm run dev` 跑，或者用 v0 的 preview 先看静态效果，确认了再点 Deploy。兜兜今天就把自己那个「一天部署 12 次」的项目改成了本地先跑——省下的不是钱，是那种「点一下没关系」的随意感。 你上一次点 Deploy 之前，真的想清楚了吗？ —— 兜兜的第 216 天 #设计工具 #Vercel #v0 #D2C #设计师钱包
